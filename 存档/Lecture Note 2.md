## 第四节 操作系统结构

- 简单结构：如 DOS 系统，应用和 OS 混在一起；在应用需求简单时可以接受
- 单体分层结构：将单体操作系统分为多层，建议上层只访问下层；但实践中通常难以严格隔离
- 微内核结构：由学术界最先提出，为了解决 OS 规模越来越大产生的问题；限制内核规模和功能，只完成最基本的功能，而尽可能将内核功能移到用户空间；未能满足应用对性能的要求，但安全性好
- 外核结构：停留在论文中；允许程序链接到操作系统库，使不同应用有定制“内核”，并自由操控系统虚拟出的硬件
- 虚拟机结构：大公司为解决服务器未能充分利用的问题，将硬件转换成很多虚拟机，卖云服务

# 第二讲 实践与实验介绍

## 第一节 实践与实验简要分析

通过满足应用逐渐增加的需求，来逐步体现操作系统的关键点。

- LibOS -> 批处理 OS -> 多道程序与分时多任务 OS
- 地址空间抽象的 OS -> 进程抽象的 OS -> 文件抽象的 OS
- 可进程间通信的 OS -> 可并发的 OS -> 管理 I/O 设备的 OS

## 第二节 Compiler 与 OS

- 异：Compiler 是把高级代码翻译成执行码的程序；而 OS 负责把这个程序跑起来。
- 同：都要面对硬件
