## 这门课讲什么

- 操作系统结构
- 中断、系统调用和异常：开发应用程序时是线性思维，第一步和第二步是连续的；开发操作系统则是断断续续的，原因就是中断、系统调用和异常；CSAPP 的第九章和 OS 相关性大
- 内存管理：内存可以申请和释放，是操作系统来管理的
- 进程管理：操作系统的重要抽象就是程序，程序之间需要共享 CPU、内存等资源
	- 处理机调度：各程序如何合理公平高效共享 CPU
- 同步互斥：有共享就有冲突，解决冲突问题；并行编程对习惯串行思维的人脑来说有难度
- 文件系统：将数据长久保存，从 Memory 导入 Storage
- I/O 子系统：使系统更丰富多彩，支持 GUI、外设等

以上解决的都是 How 的问题，但 Why？操作系统重要的是支持应用，通过操作系统的复杂能够使应用编写简单。

# 第二节 什么是操作系统

## 操作系统的定义

没有公认的精确定义。

计算机百科全书上的定义是：操作系统是管理硬件资源、控制程序运行、改善人机界面和为应用软件提供支持的一种系统软件。

操作系统是一个资源管理程序，是“承上启下”的。
- 一方面，操作系统为应用的运行提供支持；
- 另一方面，操作系统管理硬件，以便更好地支持应用。

操作系统中的软件分类：Shell, GUI, Kernel

我们说的 OS 指的是 Kernel，即在特权级模式下运行的软件。

操作系统的核心是**对应用的支持**。

rCore 是类 UNIX 的单体 OS。

## 操作系统内核的抽象

计组从 CPU 的角度考虑问题：从内存取一条指令；解析指令；取寄存器；进行计算；写回内存等等。这和编译原理比较对应。这是从执行的角度考虑。

但操作系统把 CPU 抽象成进程，把 CPU 划成不同时间段来共享使用 CPU。这是从管理的角度来考虑，管理程序分时、基于一定规则使用 CPU。

操作系统把磁盘抽象成文件，为了实现数据在磁盘和内存之间的交换。对磁盘的访问不像内存一样便捷，是一块一块（扇区）读写的。

操作系统把内存抽象成地址空间。计组认为计算机只跑一个程序，而 OS 考虑如何跑多个程序，并隔开地址空间，并让各程序认为自己独占了空间，而无需考虑内存不够。

这是“虚拟化”抽象。

操作系统使应用编写方便，但这是有限的方便。比如系统分配了 8M 的内存，程序不能超出这个限制。

## 操作系统内核的特征

- 并发：计算机系统中同时存在多个运行程序
	- 这实际上是以下特征的根本原因
- 共享：程序间“同时”访问互斥共享各种资源
	- 为什么说“互斥”？例如 CPU，一个时刻只能有一个程序在 CPU 上跑。
- 虚拟：每个程序”独占”一个完整的计算机
	- 在写代码的时候，我们不需要考虑其他程序，假定计算机只有自己用；这是因为 OS 给应用程序建立了一个 Matrix（参考黑客帝国），这是一个假象。
- 异步：服务的完成时间不确定,也可能失败
	- 体现的是不确定性，即程序执行的时间不确定。即使是同一个程序，执行几次，每次执行的时间都不同。

## 你对操作系统内核的理解

几对矛盾：
- 高效 <-> 易用
- 强大的操作系统服务 <-> 简单的接口
- 灵活性 <-> 安全性

# 第三节 操作系统历史演变

单用户系统 (1945-1955)
- 手动连线/纸带传输进行程序输入
- 机器成本远大于人力成本
- 操作系统=装载器+程序库
- 问题：昂贵组件的低利用率

批处理系统 (1955-1965)

- 磁带/磁盘传输进行程序输入
- 机器成本大于人力成本
- 操作系统=装载器+程序控制器+输出处理器
- 问题：相比以前利用率提高

多道程序系统 (1955-1980)

- 多个程序驻留内存中
- 多个程序轮流使用CPU
- 操作系统=装载器+程序调度+内存管理+输出管理
- 演变：相比以前利用率提高

分时系统 (1970-至今)

- 多个程序驻留内存中
- 多个程序分时使用CPU
- 操作系统=装载器+程序调度+内存管理+中断处理+…
- 演变：相比以前利用率提高、与外界交互延时缩短

分布式系统 (1990-)

- 分布式多用户
- 分布式系统利用率是关注点
- 重点是网络/存储/计算的效率
- 操作系统=分布式 (装载器+程序/OS调度+内存管理)
- 演变：走向大众，走向网络，新的挑战 (不可靠/不确定)

AloT 系统 (2000-)

- 分布式多设备
- 分布式系统利用率/可用性是关注点
- 重点是网络/存储/计算的效率
- 操作系统=分布式 (程序/OS调度内存管理+安全/更新)
- 演变：走向设备，走向网络，新的挑战 (不可靠/大数据)
